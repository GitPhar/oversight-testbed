# Design review of om-p2-15

## In plain English
As built, the test can answer a real question, but it is a narrower question than its card suggests. It asks whether Haiku's saved self-predictions land closer to its measured re-ratings, cell by cell and in rating points, than the guess "the shown number has no pull". The code is correct. The BCa interval matches scipy's, every dumb predictor I built fails the rule, and both outcomes are live. Two things must change before the cache is opened.

First, with only 16 vignettes the BCa interval is too narrow. A self-predictor that is, vignette by vignette, no better than the no-effect guess passes 8.4% of the time, not 2.5%. Adding a jackknife-t bound as a second condition brings that down to 2.8%.

Second, at the cell level even a predictor that knew the measured average pull for every source and distance exactly would lose to "no effect" (9.70 against 8.85 points). The effect-level reading, which the map's 55% and Sean's card were written in, is all but settled the other way by om-p2-4's published table. The frozen fail sentence and the odds record must say which question was asked.

## Checks

**D1. The rule can be applied by a stranger: holds.** `checks.py` builds a synthetic table for each verdict and runs `analyse_rows` → `sentence`:
- self = measured + N(0, 3 pts) gives **pass**: "…2.42 … against 8.85 … −6.42, 95% BCa interval [−9.76, −3.53], wholly below 0…";
- self = measured + N(0, 15 pts) gives **fail**: "…10.88 … against 8.85 … +2.03 … [−1.16, +4.92], not wholly below 0…";
- 7 of 324 self-predictions missing (2.2%) gives **untestable**: "7 of 324 kept cells have no self-prediction (more than 2%)";
- 299 rows gives **untestable**: "only 299 of 384 cells survive…".

Each table returns one verdict. The P13 boundaries (upper bound 0.0, 0.3 − 0.1 − 0.2 and −1e-4) read fail, fail and pass, as in the committed dry run. The data filter (`abs(D) < 0.05`) is a plain float compare, but no cell sits on the boundary. The nearest |D| values are 0.0440 (dropped) and 0.050000000000000044 (kept, correctly, since the rule drops only |D| < 0.05). That gives 324 of 384 kept, as §2 says.

**D2. Every manipulation takes effect: holds.** The bet has no experimental manipulation. Its knobs are the unit, the comparator and the subset, and each one moves the output. One synthetic draw (self = measured + N(0, 7.5)) gives:

| setting | Δ |
|---|---|
| points | −3.01 |
| uptake units | −0.208 |
| vs copy | −17.4 |
| copy vs zero | +14.4 |
| own cells only | −3.19 |
| other cells only | −2.83 |

The primary path is `diff_stat(metric="pts", pred="a", vs="zero")`. The parameters it uses match the pre-registration: B = 10,000, TOL 1e-9, α 0.05, `seed32_boot` read from `data/p2-15-seed.json`, leave-one-out seeds `seed32 + 1 + i`. Cache keys `U|{a,b,c}|q|o|src|d|i` match p2-4's job keys: 1,920 per arm, and all 324 kept cells have 5 integer predictions in each of a, b and c (`keys.py`).

**D3. Every control can fail: flaw (F1).** A self-predictor identical to no-uptake correctly reads fail (Δ = 0, BCa [0, 0]). The wrong set-up the rule must reject at its nominal rate is a self-predictor that is, vignette by vignette, no better than no-uptake. I simulated it by giving each cell an error magnitude drawn from the no-uptake errors of the same vignette and source, with a random sign, so the expected Δ is 0 in every vignette. Over 1,000 draws (`null.py`, `alt.py`):

| rule | false pass |
|---|---|
| frozen BCa | **0.084** |
| percentile | 0.060 |
| jackknife t (15 df) | 0.028 |
| exact vignette sign-flip | 0.036 |
| BCa **and** jackknife t | 0.028 |

The nominal one-sided rate is 0.025. The BCa computation itself is right. On one synthetic draw, the module gives [−7.145, −0.499], scipy 1.18.1 `stats.bootstrap(method="BCa", paired=True)` gives [−7.188, −0.445] and [−7.163, −0.493] on two seeds, and a hand recomputation on the module's own replicates gives [−7.145, −0.499], with z0 −0.0086 and a −0.0089 identical (`bca_check.py`). The bootstrap SD is about 5% below the jackknife SE (1.59 against 1.67, `se.py`). With z in place of t(15), the interval comes out about 14% too narrow at n = 16, so the frozen bar is about 3.4 times looser than it states. Fix F1 adds a condition and swaps nothing (P17).

**D4. Rivals are matched: holds (no fitted rivals).** Self and no-uptake are scored on the same cells against the same measured re-ratings. No-uptake is not built to win: a self-predictor that knows its shift beats it (dry run).

**D5. A dumb baseline is beaten, and the design can see the effect: holds.** Every know-little predictor I could build fails the frozen rule on program 1's measured cells (`dumb.py`, rule applied once, 10,000 resamples):

| predictor | MAE, points | result |
|---|---|---|
| no uptake (the comparator) | 8.85 | — |
| constant uptake u = 0.05, 0.1, 0.15, 0.2, 0.25, 0.3, 0.45, 0.5 | 8.66, 8.79, 9.15, 9.64, 10.22, 10.87, 13.04, 13.81 | all fail |
| label only (own u = 0.2 / 0.3 / 0.45, other 0) | 9.08 / 9.45 / 10.17 | fail |
| arm (c)'s published effect pattern | 13.44 | fail |
| Sam's published pattern | 10.58 | fail |
| the self arm's own published pattern, without cell scatter | 11.01 | fail |
| **the measured effect pattern itself (an oracle of the six effects)** | **9.70** | fail |
| copy | 23.21 | fail |

The closest is u = 0.05, at −0.19 [−0.48, +0.18]. This is not a null rule, so no equivalence margin is needed: a fail is worded "did not show". The dry run shows the effect can be seen: P(pass) is 1.00 at 5 points of noise. The oracle row matters for D8.

**D6. Foreseeable execution risks are piloted: holds.** There are no calls. Parse rate of the archive: 1,620 of 1,620 kept-cell predictions are integers in each arm, so 0 cells are missing and the 2% untestable rule will not bind.

**D7. Comparisons match: holds.** Same cells, same measured r1 and the same base; only the prediction differs. Own and other cells differ in prompt form (multi-turn versus a single "Another person estimated…" turn), but source is pooled, not contrasted, and the split is a labelled secondary. Two notes, not flaws:
- If any self-prediction were missing, `diff_stat` would average the self error over fewer cells than the no-uptake error. On a synthetic table with 17 missing: 307 cells against 324. This is moot here (0 missing), but it should restrict both to the same cells if the code is reused.
- §2 states SHA-256 prefixes, but the code never checks them. Both match today (`a711ab441d69124d`, `bdeef6909a6208c4`).

**D8. The verdict sentences are written: flaw (F2).** Sentences exist for pass, fail, untestable and both leave-one-out cases, and they are frozen in `SENTENCES`. Three problems:
1. **Fail sentence.** The design makes a fail compatible with self-predictions that match the measured average pattern perfectly. The six-effect oracle loses at the cell level (9.70 against 8.85). Meanwhile, om-p2-4's published effects give the effect-level version, point estimate, as self 0.064 against no-uptake 0.297 uptake units. "This test did not show that its self-predictions beat assuming no effect" is literally true. Under the title "Do the model's predictions of its own quirks beat a guess of no effect?" it will be read as "they don't know their quirks", which the design cannot carry (P9).
2. **Event fidelity.** The card and the map event say "self-prediction error on the uptake cells". Cell-level is a fair reading of those words, and rating points are a sound unit (the dry run shows uptake units let |D| ≈ 0.05 cells decide). But the map's 0.55 rationale ("self error (0.054) is small … measured uptake 0.21–0.71 … far from zero") is om-p2-4's effect-level error in uptake units. Under that reading the event is near-certain; under this one, an effect-level oracle fails. Sean's 0.70 must be carried (H1 holds), but the record must say that he answered a card written in the other frame.
3. **Two smaller wording problems.**
   - §6 says no-uptake "is strong where measured shifts are small (most other-source cells)". On program 1's cells, in points, other-source shifts are as large as own: mean 8.76 against 8.93, median 3.76 against 5.66, and 40% against 41% under 3 points.
   - The leave-one-out flip sentence prints "without co01, co02, co03, the rule reads fail" (`checks.py`, three-vignette world). That reads as removing all three together; it means any one of them.

**D9. One item cannot decide it: holds.** Leave-one-vignette-out re-applies the rule with its own 10,000-resample BCa (seeds seed32 + 1 + i). Its outcome is frozen: reported, label unchanged. On a world where self is exact on three vignettes and equals no-uptake elsewhere, the result is pass [−2.69, −0.11], with flips listed for each of the three (`checks.py`). The smallest leave-one-out subset is 300 cells (vignettes keep 12–24 cells), so no leave-one-out run falls under the 300-cell untestable rule. It is exactly at the line, but not under it.

**D11. The bet can both pass and fail: holds.** The pre-registration's named worlds give P(pass) 1.00 (knows its shift, 5 pts), 0.79 (7.5 pts) and 0.00 (knows nothing).

Those worlds use assumed Gaussian noise (P15). One measured cell-level number exists on the exact prompts: om-p2-4's exploratory r(self, measured) = 0.87 on the U cells. For comparison, the no-uptake predictor alone reaches r = 0.904 on the 384 cells (`calib.py`). Worlds calibrated to that number split by error shape:
- Gaussian worlds with r near 0.87 need about 15 pts of noise, so P(pass) is about 0.
- Heavy-tailed worlds track most cells exactly and miss whole cells. Under the frozen rule they give P(pass) 0.42 (r 0.86), 0.69 (r 0.92) and 0.73 (r 0.85, adversarial misses) (`mix2.py`, `d11fix.py`).
- Under F1's rule (BCa and jackknife t), the same worlds give 0.20, 0.33 and 0.56, with the 5-pt world still 1.00 and know-nothing worlds 0.00.

The result is not known before it runs, and the engine's 0.18 is consistent with this. Whether 0.87 was computed on cell means or on single predictions is not recorded; on single predictions the passing worlds become more plausible.
