# GDumb: a simple approach that questions our progress in continual learning — Ameya Prabhu, Philip H. S. Torr, Puneet K. Dokania, 2020, ECCV 2020
- url: https://www.robots.ox.ac.uk/~tvg/publications/2020/gdumb.pdf (author PDF)
- field: metascience
- read_depth: partial (abstract, problem formulation and assumptions, method, results for formulations A1-A3 and B1-B3; formulations C-E and the appendix not read)
- read_by: scout-bmq reader F, 2026-11-04
- what_tested: Whether a deliberately "dumb" baseline beats published continual-learning methods on the formulations each method was designed for. GDumb stores a class-balanced random memory greedily and, at test time, trains from scratch on that memory only.
- on_whom: MLPs, ResNets and CNNs on MNIST, SVHN, CIFAR-10, CIFAR-100 and ImageNet100, across 10 CL formulations (online/offline, class- or task-incremental). 3 seeds. Compared with about 30 published methods (EWC, SI, MAS, LwF, GEM, A-GEM, iCaRL, ER, MIR, DGR, GEN, BiC, PODNet, among others).
- how_scored: Final test accuracy under each formulation's published protocol and memory budget. GDumb uses one fixed hyperparameter setting with no tuning.
- result: A1, CIFAR-10 at k = 200/500/1000: GDumb 35.0 / 45.8 / 61.3 vs. the best published method (ER-MIR) 29.8 / 40.0 / 47.6. MNIST at k = 500: 91.9 vs. 87.6. A3, CIFAR-10: GDumb 61.3, ER 41.3, generative replay (GEN) 15.3 despite a larger memory footprint. Experience replay beats generative replay "with much smaller memory footprint". B1, MNIST: regularisation methods without memory score 19.5-19.8 (EWC 19.8, SI 19.7), against GDumb 97.8. B2 (20 tasks, CIFAR-100) is an exception: GDumb 24.1 last-task accuracy vs. BiC 46.9, iCaRL 42.9, so it does not win everywhere.
- limits: Vision classification only. GDumb needs to store raw data and retrain, and it cannot learn without memory. Results follow each paper's own protocol, so they are cross-paper comparisons.
- borrow: The "dumb replay" baseline belongs in every T3/T7 pre-registration. Before testing "dreamed" (self-generated) replay or "triage" (selective) replay in LoRA fine-tuning of Llama/Qwen, include (a) random replay of a small stored sample of the old data at the same token budget, and (b) where cheap, retraining the adapter from scratch on that stored sample. If the biomimetic arm does not beat (a), the borrowed mechanism adds nothing. Here generative replay lost badly to stored replay at a smaller memory budget.
- next_steps_it_suggests: Use GDumb as a sanity-check baseline; design CL formulations with fewer simplifying assumptions (no task boundaries, open-set classes).
- already_run_check: Nearly runs T3 (generative replay vs. stored replay vs. none), in vision networks, not LLMs. The result is that generative replay loses to plain stored replay.
- transfers: partly — the metascience lesson, that published CL gains often vanish against a trivially simple memory baseline, transfers directly. Whether an LLM's self-generated replay does better than image GANs is open, and that is what T3 would test.
